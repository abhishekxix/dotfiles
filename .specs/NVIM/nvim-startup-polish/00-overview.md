# Nvim Startup + Polish

| Field | Value |
|---|---|
| Status | Approved |
| Component | NVIM |
| Created | 2026-09-09 |

## Goal

Trim Neovim startup cost (lazy-load what loads eagerly for no reason) and fix
small correctness/polish gaps found in the audit — without touching
`keymaps.lua`, copilot, virtual text, or completion sources (all decided in
slice 1: keymaps reverted, copilot stays eager, no buffer source).

## Context & Research

Second slice from the 2026-09-09 five-agent audit. Two prior decisions
constrain this spec:

1. The `robustness-and-optimization` spec (Done) deliberately left
   `copilot.vim` eager and deferred `opts.lua` polish — this spec does not
   relitigate either.
2. Slice 1 (`nvim-editing-workflow`) reverted all `keymaps.lua` changes per
   user request. So the `<leader>st` TodoTelescope binding goes in the
   plugin's own `keys` table (lazy-loads the plugin as a side effect —
   standard lazy.nvim pattern), **not** in `keymaps.lua`.

Key facts:

1. **telescope on `VimEnter`** (`telescope.lua:4`): loads telescope + fzf-native
   on every `nvim file` startup even when never invoked. All its keymaps are
   `<leader>s*`/`<leader>/` etc. — a `keys` table replaces the event with
   zero behavior change. `ui-select` extension still registers on first use.
2. **todo-comments on `VimEnter`, no keymaps** (`todo-comments.lua`): pays
   startup for gutter-invisible TODOs (`signs = false`) with no way to reach
   them. `keys = <leader>st → TodoTelescope` both lazy-loads and makes the
   plugin reachable.
3. **opencode fully eager** (`opencode.lua:1`): no `cmd`/`keys`/`event` — pays
   AI-plugin startup on every launch. Its keymaps are the lazy trigger.
   (`<C-a>` hijack noted in audit but explicitly out of scope — muscle-memory
   decision deferred to a keymap-review spec.)
4. **mini.nvim fully eager** (`mini.lua:2`): loads ai/surround/indentscope/move/
   statusline at startup. `event = 'VeryLazy'` defers to after UI render;
   statusline appears on first paint either way (VeryLazy fires before first
   render completes… in practice no visible flash; verify manually).
5. **neo-tree noise** (`neo-tree.lua:26-30`): `visible = true` +
   `hide_dotfiles = false` + `hide_gitignored = false` shows `.git/`,
   `node_modules/`, dotfiles — noise on every reveal. No `follow_current_file`
   means `nvim <dir>/` never tracks. `filtered_items` fix is display-only;
   `follow_current_file.enabled = true` changes reveal behavior (verify).
6. **treesitter non-parser filetypes** (`autocommands.lua:13`): pattern from
   `langs.get_filetypes()` includes `zsh`, `yaml.docker-compose`,
   `javascriptreact` — none is a parser name, so `vim.treesitter.start()`
   raises and the pcall notifies ERROR on every such buffer. Fix: guard the
   callback to only `start()` when a parser exists
   (`vim.treesitter.language.add` / parser lookup), else skip silently.
7. **which-key gaps** (`which-key.lua:10-18`): groups exist for c/d/r/s/w/t/h/m/p
   but slice 1 added `<leader>f` (format), `<leader>tf`, `<leader>tc`
   (copilot) with no groups — popup shows them ungrouped. Add `f` group.
8. **lint staleness** (`lint.lua:11`): autocmd misses `TextChanged` — eslint /
   shellcheck results go stale while editing without save. Cheap add.
   (`BufEnter` over-firing noted in audit but harmless; leave it.)

## Non-goals

- Do **not** touch `lua/keymaps.lua` (user decision, slice 1).
- Do **not** lazy-load or otherwise change `copilot.vim` (prior spec decision).
- Do **not** change opencode `<C-a>`/`<C-x>`, `<C-hjkl>`, clipboard scheme,
  mini.surround maps, cmp sources, virtual text (deferred to keymap-review).
- Do **not** add new plugins or new autocmds (no VimResized/CheckTime/last-place
  — separate spec).
- Do **not** touch `langs.lua`, `lazy-config.lua`, `lazy-lock.json`
  (regenerated by `:Lazy sync` if plugin specs change deps).

## Steps

Each step maps to exactly one commit, named `NVIM(<NN>): <summary>`.

### 01 — Lazy-load telescope on keys

- **Files:** `lua/plugins/telescope.lua` (EDIT)
- **Changes:** replace `event = 'VimEnter'` with a `keys` table carrying the
  existing `<leader>s*`, `<leader>/`, `<leader><leader>` bindings (moved from
  the `config` function, same rhs/desc). `ui-select` still loads on first use.
- **Test:** `nvim --headless file.txt -c 'lua assert(not package.loaded["telescope"], "eager")' -c 'qa!'`; then press `<leader>sf` manually and confirm picker opens
- **Acceptance:**
  - [ ] telescope not loaded at startup; every existing binding still opens its picker

### 02 — Lazy-load todo-comments + add TodoTelescope key

- **Files:** `lua/plugins/todo-comments.lua` (EDIT)
- **Changes:** replace `event = 'VimEnter'` with
  `keys = { <leader>st → TodoTelescope }`. (New binding lives in the plugin
  spec, not `keymaps.lua`, per slice-1 decision.)
- **Test:** startup assert as above; `<leader>st` opens TodoTelescope
- **Acceptance:**
  - [ ] plugin not loaded at startup; `<leader>st` works

### 03 — Lazy-load opencode on its keys

- **Files:** `lua/plugins/opencode.lua` (EDIT)
- **Changes:** move the existing `vim.keymap.set` calls into a lazy.nvim
  `keys` table (same lhs/rhs/desc). No binding changes.
- **Test:** startup assert for `opencode`; trigger one binding manually
- **Acceptance:**
  - [ ] plugin not loaded at startup; all existing bindings work unchanged

### 04 — Defer mini.nvim to VeryLazy

- **Files:** `lua/plugins/mini.lua` (EDIT)
- **Changes:** add `event = 'VeryLazy'`. No config changes.
- **Test:** normal `nvim file` open — confirm statusline present on first paint, no flash; `:Lazy profile` shows mini after startup
- **Acceptance:**
  - [ ] statusline renders normally; mini loads post-startup

### 05 — Neo-tree follow + hide noise

- **Files:** `lua/plugins/neo-tree.lua` (EDIT)
- **Changes:** `follow_current_file.enabled = true`; `hide_dotfiles = true`,
  `hide_gitignored = true` (keep `visible = true` so they're one keystroke
  away with `H`).
- **Test:** open `nvim <dir>/file`, confirm tree reveals and tracks; `.git/` hidden until `H`
- **Acceptance:**
  - [ ] tree follows current file; ignored/dotfiles hidden by default, toggleable

### 06 — Guard treesitter start to real parsers

- **Files:** `lua/autocommands.lua` (EDIT)
- **Changes:** in the FileType callback, skip `vim.treesitter.start()` (and
  foldexpr/foldmethod) when no parser exists for the buffer's filetype, so
  `zsh`/`yaml.docker-compose`/`javascriptreact` stop spamming ERROR
  notifications. Keep the pcall + notify for genuine load failures.
- **Test:** open a `.zsh` file and a `docker-compose.yml` — no notification; open a `.lua` file — highlighting + folds active
- **Acceptance:**
  - [ ] no error spam on parser-less filetypes; highlighting intact elsewhere

### 07 — which-key format group + lint on TextChanged

- **Files:** `lua/plugins/which-key.lua` (EDIT), `lua/plugins/lint.lua` (EDIT)
- **Changes:** add `{ '<leader>f', group = '[F]ormat' }` (covers `<leader>f`
  and `<leader>tf`). Add `TextChanged` to the lint autocmd events.
- **Test:** `:checkhealth which-key` clean; edit a `.sh` file without saving, confirm lint refreshes
- **Acceptance:**
  - [ ] `<leader>f` grouped in popup; lint no longer stale mid-edit

## Risks & Rollback

- **Lazy-loading (steps 01–04):** if a `keys` entry is mistyped, the binding
  silently vanishes. Mitigation: the acceptance check presses every moved
  binding. Rollback: `git revert` restores the event.
- **mini VeryLazy (step 04):** statusline could flash on slow machines —
  verify visually; revert if so.
- **neo-tree follow (step 05):** changes reveal behavior (`nvim <dir>/`
  now tracks); if annoying, revert just this commit.
- **treesitter guard (step 06):** if the parser check is too strict,
  highlighting could silently disable for a filetype that worked — verify
  `.lua`/`.py`/`.ts` manually.

Each step is its own commit, so `git revert` or `git bisect` localizes any
regression.
